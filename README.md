# Trommel

Харнес-линтер прогона правил проектирования: DDD, чистая архитектура и прочие. Прогоняет
кодовую базу через набор правил и сообщает о расхождениях с выбранной архитектурной нормой.

## Назначение

Архитектурные нормы — предметно-ориентированное проектирование (Domain-Driven Design, DDD),
чистая архитектура (Clean Architecture), разделение команд и запросов (Command Query
Responsibility Segregation, CQRS) — описаны текстом и держатся на договорённости. Trommel
делает их проверяемыми: правило становится прогоном, а расхождение — отчётом, а не замечанием
на ревью.

Харнес задаёт единый способ подключать правила разных норм и прогонять их по кодовой базе
одной командой.

## Состояние

Проект в начале работы: заведён репозиторий и окружение разработки, содержательной части ещё
нет. Состав правил, формат отчёта и способ подключения кодовой базы определяются
спецификациями в `openspec/`.

## Окружение разработки

В репозитории развёрнут [SDD Developer Kit](https://github.com/united-software-platform/sdd-developer-kit) —
контейнер с агентом и инструментами Spec-Driven Development (SDD). Порядок подготовки:

```bash
make init
```

Дальше — по шагам README набора: заполнить `.env` (`GIT_HOST`, `CLAUDE_PROFILE`), повторить
`make init`, зарегистрировать публичный ключ в git-сервисе и запустить контейнер. Перечень
команд — `make help`.

## Правила репозитория

Нормы документации, терминологии, чтения, `Makefile` и Git лежат в [`rules/`](./rules)
и подключаются агенту через [`CLAUDE.md`](./CLAUDE.md). Там же — правила предметной области
харнеса: [DDD](./rules/ddd.md), [чистая архитектура](./rules/clean-architecture.md)
и [CQRS](./rules/cqrs.md).
