## Why

> **Зависимость:** изменение опирается на `prepare-rule-foundation` — общий обход дерева,
> реестр предметов, область действия правила и параметры-конвенции. Без них партия
> начиналась бы с перестройки ядра под себя.

Работа идёт по готовности правила, а не по его группе. Внутри каждой группы готовность
разная: в `DOCK` одиннадцать правил замкнуты и четыре остаются суждением, в `GIT` четыре
проверяемы и восемь описывают действия. Нарезка изменений по группам смешивала бы
понятное с невозможным и заставляла бы каждый раз заново отделять одно от другого.

Сводка покрытия `COVERAGE.md` теперь ведёт этот отбор сама: раздел «Можно делать»
перечисляет правила, у которых предмет поддержан или вводится вместе с ними, а
формулировка задаёт границу множества нарушений. Это изменение берёт оттуда всю партию —
восемнадцать правил.

## What Changes

- **Вводится предмет «конфигурация контейнеров»** — YAML конфигурации Compose
  и построчный разбор `Dockerfile`. Разблокирует одиннадцать правил. Опирается
  на механизм предметов, построенный в `prepare-rule-foundation`.
- **Реализуются восемнадцать правил**: `DOCK-001`, `DOCK-002`, `DOCK-003`, `DOCK-004`,
  `DOCK-007`, `DOCK-009`, `DOCK-010`, `DOCK-011`, `DOCK-012`, `DOCK-013`, `DOCK-015`,
  `DOC-013`, `GIT-006`, `GIT-009`, `GIT-012`, `GIT-021`, `TERM-003`, `TERM-008`.
- **Правило, у которого при реализации обнаружится незамкнутость формулировки,
  возвращается в состояние «трудность»** с описанием препятствия, а не реализуется
  приблизительно. Это относится прежде всего к `GIT-012`: перечень форм подписи агента
  может оказаться открытым.

## Capabilities

### New Capabilities

- `container-rules`: проверка конфигурации контейнеров — имена и префиксы сервисов, сеть,
  источники значений окружения, политика перезапуска, пользователь контейнера приложения,
  порядок запуска.
- `commit-message-rules`: проверка текста сообщения коммита — формат заголовка, наличие
  тела, отсутствие служебных подписей, исключение для машинного релизного коммита.
- `repository-rules`: проверка состояния репозитория — имя рабочей ветки.

### Modified Capabilities

Отсутствуют: механизмы, на которые опираются эти правила, строит
`prepare-rule-foundation`.

## Impact

- **Новый предмет проверки** — конфигурация контейнеров, первый читающий не Markdown.
- **Связка с хуком**: появляется первый случай, когда вердикт предназначен не человеку.
- **Сводка покрытия** отражает прирост прогоном; правило, вернувшееся в «трудность»,
  уходит из рабочего списка с описанием препятствия.
