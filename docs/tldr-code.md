# Анализатор кода tldr-code

Возможности внешнего анализатора кода tldr-code в том объёме, в каком на него опирается Trommel:
уровни разбора, формы вызова команд, границы полноты вывода и поведение при отказе.

## Назначение

tldr-code — анализатор исходного кода, выдающий структурированное описание кодовой базы:
структуру модулей, граф вызовов, поток данных, зависимости между модулями. Вывод рассчитан
на машинную обработку, а не на чтение человеком.

Trommel использует его как источник фактов о коде: правила предметной области — чистой
архитектуры, Domain-Driven Design (DDD) и разделения команд и запросов (Command Query
Responsibility Segregation, CQRS) — проверяют не текст файла, а факты, полученные разбором.

Сведения ниже сняты с выпуска `0.4.0` сборки `x86_64-unknown-linux-gnu` и проверены прогоном
по дереву самого Trommel.

Архив выпуска содержит три исполняемых файла и сопроводительные документы:

| Файл | Назначение |
|------|------------|
| `tldr` | Командная строка анализатора — единственное, что требуется Trommel |

## Уровни разбора

Анализатор объявляет пять уровней. Принадлежность команды уровню взята из его собственной
справки, а не из документации репозитория: они расходятся в отнесении команд потока данных.

| Уровень | Предмет | Команды |
|---------|---------|---------|
| L1 AST | Структура файла: функции, классы, импорты, определения | `tree`, `structure`, `extract`, `imports`, `importers` |
| L2 Call Graph | Вызовы между файлами и модулями | `calls`, `impact`, `dead`, `hubs`, `whatbreaks` |
| L3 CFG | Достигающие определения и доступные выражения | `reaching-defs`, `available` |
| L4 DFG | Присваивания, результат которых не используется | `dead-stores` |
| L5 PDG | Срезы программы: от чего зависит точка | `slice`, `chop`, `taint` |

Зависимости между модулями выдаёт команда `deps`: она строит граф импортов, перечисляет
циклы и считает метрики связности. Уровню в справке анализатора она не приписана, хотя
по предмету примыкает к L1.

## Проектные и точечные команды

Команды делятся на два рода, и это различие определяет, что можно собрать обходом дерева,
а что — только по конкретному запросу.

**Проектные** принимают необязательный путь и обходят дерево целиком:

```bash
tldr structure /project --format json
tldr calls /project --format json
tldr deps /project --format json
tldr dead /project --format json
```

**Точечные** требуют цель — файл, функцию, строку или символ — и без неё не вызываются:

```bash
tldr extract /project/internal/harness/harness.go
tldr imports /project/internal/harness/harness.go
tldr reaching-defs /project/internal/harness/harness.go Run
tldr slice /project/internal/harness/harness.go Run 48
tldr impact Run /project
```

> **Важно:** уровни L3, L4 и L5 доступны только точечными командами. Собрать их обходом
> дерева одной командой нельзя: каждая отвечает на вопрос о конкретной функции или строке,
> поэтому число обращений растёт с числом функций области.

Замер на выпуске `0.4.0`: четыре точечные команды на одну функцию стоят около **0,03 секунды
и 5,6 КБ вывода**. Проект из 56 файлов PHP и 131 функции снимается целиком за **4 секунды**;
проект из 36 859 файлов PHP только на `structure` тратит **181 секунду и 75 МБ**.

## Команды вне уровней

Анализатор даёт и то, что к уровням разбора не отнесено и Trommel как источник фактов
не используется:

- метрики качества: `complexity`, `cognitive`, `halstead`, `loc`, `churn`, `debt`, `health`,
  `hotspots`, `clones`, `cohesion`, `coupling`;
- безопасность: `secure`, `vuln`, `api-check`, `resources`;
- архитектура и контракты: `patterns`, `inheritance`, `surface`, `contracts`, `specs`,
  `invariants`, `verify`, `interface`;
- поиск и пояснение: `search`, `context`, `definition`, `explain`, `references`, `diff`;
- сводные: `todo`, `fix`, `bugbot`, `diagnostics`, `doctor`, `coverage`, `stats`.

Команды семантического поиска (`semantic`, `similar`, `embed`) в сборку выпуска не входят:
они требуют сборки с признаком `semantic` и загрузки модели около 110 МБ.

## Формы вывода ответов о функции

Ответы точечных команд устроены вокруг базовых блоков функции. Ниже — поля, по которым
снимаются факты; остальное относится к внутреннему представлению анализатора.

| Команда | Аргументы | Поле ответа | Что в нём |
|---------|-----------|-------------|-----------|
| `reaching-defs` | файл, функция | `blocks[].gen[]` | `var`, `line` — определение, достигающее блока |
| `available` | файл, функция | `avail_in{}` | `text`, `line` — выражение, доступное на входе блока |
| `dead-stores` | файл, функция | `dead_stores_ssa[]` | `variable`, `line` — присваивание без использования |
| `slice` | файл, функция, строка | `slice_lines[]` | `line`, `dep_type` — строка среза и род зависимости |

Команды `taint` и `chop` фактов не дают и в съём не входят: `chop` требует двух строк,
для которых нет осмысленного умолчания, а у `taint` на доступных корпусах поля `sources`,
`sinks` и `flows` оставались пустыми — форма их элементов не проверена, и разбор был бы
догадкой.

---

## Формы вывода

Ключ `--format` общий для всех команд; умолчание — `json`.

| Форма | Доступность |
|-------|-------------|
| `json` | Все команды |
| `text` | Все команды |
| `compact` | Все команды |
| `sarif` | Только `vuln`, `clones` |
| `dot` | Только `calls`, `impact`, `hubs`, `inheritance`, `clones`, `deps` |

Запрос формы, которую команда не выдаёт, отклоняется с указанием допустимых команд.

## Коды возврата

| Код | Значение | Пример |
|-----|----------|--------|
| `0` | Команда выполнена | Разбор состоялся; вывод в `stdout` |
| `1` | Ошибка выполнения | Путь не существует; форма вывода не поддержана командой |
| `2` | Ошибка вызова | Неизвестная команда, язык или значение ключа |

> **Внимание:** код `0` не означает, что факты получены. Каталог без поддержанных файлов даёт
> код `0`, пустой перечень файлов, `language: null` и предупреждение `No source files found
> in directory`. Вызывающая сторона обязана отличать «разобрано и пусто» от «разбирать
> было нечего».

## Полнота вывода

Вывод усекается по умолчанию, и усечение видно в самом выводе.

Команда `calls` ограничивает число рёбер ключом `--max-items` со значением по умолчанию `200`
и сообщает три поля: `truncated`, `total_edges`, `shown_edges`.

```json
{ "truncated": true, "total_edges": 191, "shown_edges": 5 }
```

> **Внимание:** значение `0` у `--max-items` не снимает ограничение, а даёт пустой вывод
> с признаком `truncated: true`. Полный граф получается значением, заведомо превышающим
> `total_edges`, с последующей проверкой признака усечения.

Команда `deps` сообщает число пропущенных файлов полем `files_skipped`, `structure` —
перечень предупреждений полем `warnings`.

## Язык проекта

Язык определяется автоматически и один на прогон: вывод содержит поле `language` с единственным
значением. Ключ `--lang` задаёт язык явно; неизвестное значение отклоняется кодом `2`.

Прогон `tldr structure` по дереву Trommel дал `language: "go"` и 27 файлов — ровно столько,
сколько файлов `.go` в дереве. Файлы других языков в вывод не попали и в предупреждениях
названы не были.

> **Важно:** в проекте на нескольких языках один прогон описывает один язык. Полнота требует
> прогона на каждый язык и перечисления того, что не разобрано ни одним из них.

## Область обхода

Собственного ключа исключения каталогов у команд нет. Сужение области возможно двумя способами:

- путём в аргументе команды — обход ограничивается указанным подкаталогом;
- ключом `--respect-ignore` у команды `calls` — учитываются образцы `.gitignore`
  и `.tldrignore` проверяемого проекта.

Ни один из способов не годится как основание для сужения области прогона Trommel: первый
не выражает произвольный перечень исключений, второй зависит от файлов проверяемого проекта
и поддержан не всеми командами. Область сужается разбором вывода на стороне Trommel.

## Режим демона и MCP-сервер

`tldr daemon start`, `tldr warm <путь>`, `tldr daemon stop` поднимают службу с кешем в памяти;
ключ кеша строится по имени команды, её аргументам и времени изменения файлов. Trommel демон
не использует: вердикт обязан зависеть от содержимого, а не от времени изменения файлов.

`tldr-mcp` — отдельный сервер MCP на транспорте stdio, предоставляющий 24 инструмента разбора
агенту. Канал агента, а не харнеса: к прогону Trommel отношения не имеет.

## Установка

Выпуски публикуются на GitHub. Каждый актив сопровождается файлом контрольной суммы:

```bash
base=https://github.com/parcadei/tldr-code/releases/download/v0.4.0
asset=tldr-cli-x86_64-unknown-linux-gnu.tar.xz

wget "$base/$asset" "$base/$asset.sha256"
sha256sum -c "$asset.sha256"
tar -xf "$asset"
```

Сборка из исходников требует Rust 1.70 и выше:

```bash
cargo install tldr-cli
```

> **Внимание:** активы выпусков собраны под `gnu`; сборок под musl нет ни в одном выпуске,
> хотя документация анализатора их обещает. В образе на основе Alpine такой бинарник
> не запускается.

## Съём фактов проекта

Срез снимается целью `make trommel-facts`. Анализатор при этом живёт в образе Trommel,
на хост не ставится, а снимаемый проект монтируется только на чтение.

```bash
make trommel-facts PROJECT=/путь/к/проекту
make trommel-facts PROJECT=/путь/к/проекту SCAN=lib FACTS_FORMAT=json
make trommel-facts PROJECT=/путь/к/проекту LEVELS=L1,L2 SCAN=src SCAN=lib
```

| Переменная | Умолчание | Назначение |
|------------|-----------|------------|
| `PROJECT` | — (обязательна) | Каталог снимаемого проекта **на хосте** |
| `SCAN` | пусто | Сканируемые пути карты; пусто — проект целиком |
| `LEVELS` | пусто | Уровни съёма; пусто — все известные |
| `FACTS_FORMAT` | `text` | `text` — сводка человеку, `json` — срез машине |
| `FACTS_DIR` | `facts` | Куда класть срез; каталог в репозиторий не коммитится |

Срез кладётся в `$FACTS_DIR/<имя проекта>.json` либо `.txt` — отдельным файлом на проект.

> **Внимание:** `PROJECT` — путь на хосте, а не внутри контейнера агента. Каталог `projects/`
> внутри контейнера образован монтированиями `docker-compose.yml`; на хосте он пуст, и съём
> по нему дал бы пустой срез. Цель проверяет это явно и отказывает, а не выдаёт пустоту.

Тот же съём напрямую, без `make` — например, когда анализатор лежит рядом, а не в образе:

```bash
trommel --facts --project /путь/к/проекту --scan lib --level L1 --level L2
```

## Границы применимости

- Языков поддержано 18, среди них Go, Python, TypeScript, JavaScript, Rust, Java, C, C++.
  Файл на другом языке в вывод не попадает и в предупреждениях не называется.
- Номер версии — `0.4.0`: состав команд и форма вывода меняются между выпусками без обещания
  совместимости. Версия закрепляется, а её смена проверяется заново.
- Лицензия AGPL-3.0 распространяется на сам анализатор. Вызов отдельным процессом компоновкой
  не является; распространение образа, содержащего анализатор, подчиняется условиям его
  лицензии.
- Разбор не изменяет разбираемое дерево: прогон по дереву Trommel не создал и не изменил
  ни одного файла и не оставил данных в домашнем каталоге пользователя.
